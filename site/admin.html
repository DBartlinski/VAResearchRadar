Overview

VA Research Radar is a daily pipeline that aggregates, scores and publishes Veterans Affairs research publications from PubMed, OpenAlex and Crossref, with funding attribution. It is published as a static dashboard on GitHub Pages.

How a run works

  1. Query PubMed, OpenAlex and Crossref for records within the lookback window.
  2. Merge duplicates across sources and classify VA funding.
  3. Score each record into High, Medium or Low priority.
  4. Store records in the database (data/vadaily.db), keeping first-seen dates for the “Added” day pills.
  5. Write the dashboard data files to site/data.

Local setup

  1. Install Python 3.12 or newer.
  2. Create and activate a virtual environment. 
    python -m venv .venv
.venv\Scripts\Activate.ps1
  3. Install dependencies. 
    pip install -r requirements.txt
  4. Optionally set NCBI_API_KEY and OPENALEX_API_KEY to raise API rate limits, and set contact_email in config/settings.yaml.

Running the pipeline

Refresh locally. This writes site/data/ and data/vadaily.db.

python -m vadaily.pipeline

To view the dashboard locally, serve the site folder, for example:

python -m http.server 8000 --directory site

Then open http://localhost:8000.

Tests

python -m pytest -q

Publishing

The workflow Refresh data and deploy site (.github/workflows/pages.yml) refreshes the data and deploys the site folder to GitHub Pages.

Manual runActions tab, choose the workflow, then Run workflow (workflow_dispatch).

SecretsOPENALEX_API_KEY (optional) enables cursor paging in OpenAlex.

DeployA separate job, so a failed deploy can be re-run without rebuilding the data.

Pull before you push

The workflow pushes “Refresh data” commits to main every day. Run git pull --rebase before pushing your own changes.

Configuration

All settings live in config/settings.yaml.

SettingPurpose
start_datePublications dated before this are ignored.
lookback_daysHow many days back PubMed and OpenAlex are re-queried each run (never earlier than start_date).
contact_emailContact email sent with NCBI and OpenAlex API requests.
pathsLocations of the database and the site output.
pubmedEnable flag and the affiliation and grant query. Optional NCBI_API_KEY environment variable raises the rate limit.
openalexVA institution and funder IDs. Leave institution_ids empty to auto-resolve “Department of Veterans Affairs”.
scoringTiers, topics, study designs, journal tiers, funding and penalties (see below).

Scoring

Each record receives a point total. Totals of 45 or more are High, 25 or more are Medium, and the rest are Low (scoring.tiers).

  • Veteran in title: keywords such as veteran*, military, service member*.
  • Topics: weighted keyword groups, for example suicide prevention, toxic exposures / PACT Act, Million Veteran Program, PTSD, TBI and homelessness.
  • Study designs: randomized trials, meta-analyses, Cooperative Studies Program, large national studies and more. Prefix a keyword with re: to use a raw regular expression.
  • Journal tier: based on OpenAlex 2-year mean citedness, with name overrides in always_top and always_mid.
  • Funding: higher weight for ORD-funded than VA-funded-only work.
  • Penalties: preprints, conference abstracts, editorials and letters, errata, retractions and non-health records.

To tune results, edit the weights or keywords and rerun the pipeline.

Troubleshooting

“Added” dates reset

Check that the “Refresh data” commit step succeeded in the workflow log and that data/vadaily.db was committed. Without the database, every record is treated as new.

Rate-limit or empty results

Confirm the OPENALEX_API_KEY secret is set (and NCBI_API_KEY, if used) and that contact_email is filled in.

A record is missing

It may be dated before start_date, older than lookback_days, or not matched by the PubMed query or OpenAlex VA institution and funder IDs. Adjust config/settings.yaml and rerun.

Workflow fails to deploy

Confirm GitHub Pages is enabled for the repository and that the workflow has Pages and ID-token permissions.
